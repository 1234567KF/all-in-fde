# 长文/文档 playbook

适用于标书、专利、软著、团标、申报书、白皮书、合同、知识库长文，以及审阅/扩写/润色/改写。

## 1. 任务前：先建索引，不读全文

1. 确认对象：文件路径、版本、字数、章节数、交付格式。
2. 生成大纲：标题层级 + 行号区间 + 每节一句话摘要。
3. 标出本次范围：只审哪几章、只改哪几节、哪些不动。
4. 判断峰谷：长生成（扩写/重写）尽量放低谷；审阅/核对可放高峰。

产出（写到文件，不贴全文）：

```text
outline.md
- 1 总则 ......... L1-L40  （范围/术语）
- 2 技术要求 ..... L41-L180（指标/流程）
...
```

## 2. 审阅：按节读，按条报

- 一次只读 1–2 节；用 `read` 的 offset/limit。
- 每条问题给：文件 + 行号 + 原文摘录（≤2 行）+ 问题类型 + 建议。
- 分级：P0（事实/法律/硬伤）、P1（覆盖/一致性）、P2（表达）。
- 不把整篇文档贴进对话；引用位置即可。
- 审阅结论先写文件，对话只给“P0 数量 + 3 条最严重 + 文件路径”。

## 3. 改写/扩写：diff 优先

- 先给结构/要点，确认后再展开；不要一上来重写全文。
- 输出“替换块”：`原文行号 → 新文本`，或 unified diff。
- 新增内容标出来源/依据；找不到依据就写“待补”，不编造。
- 保留原有编号、术语、格式；不改变未要求的段落。
- 长文扩写按章节分批，每批结束落盘，避免一次生成几万字。

## 4. 压缩与上下文

- 只在章节边界做压缩；保留“决策、术语、未决问题、数据口径”清单。
- 不要压缩文档正文；不要用摘要替代原文做事实核对。
- 同一文件不重复整读；需要时读行区间或让子代理读后回报。
- 子代理 brief 里写明“只读第 X 章，返回 ≤1500 token，问题写文件”。

## 5. 交付

对话里只给：

1. 交付文件路径；
2. 变更摘要（3–5 条）；
3. 未决问题/需要人工确认项；
4. 验收方式（怎么检查）。

不要把全文、整章、整份 diff 贴回对话。

## 6. 验收清单

- [ ] 范围没扩大，未要求改的段落没动
- [ ] 编号/术语/格式一致
- [ ] 每条修改有依据或标“待补”
- [ ] 交付文件可打开、页码/章节正确
- [ ] 有 `#task` 标签，便于 `verify`
