# 策略与红线

本文件是 `token-budget` 的决策表。只在 `plan` 判断需要时读，不要整篇塞进上下文。

## 1. 成本项与杠杆排序

按当前账单（输出 40%、缓存命中输入 35%、未命中 25%、高峰占 69.8%）排序：

| 优先级 | 杠杆 | 典型上限 | 质量风险 |
| ---: | --- | ---: | --- |
| 1 | 低谷调度 | ~35% | 无 |
| 2 | 输出/effort 降档 | 8–15% | 低–中 |
| 3 | 上下文纪律（大纲/分节/落文件） | 10–18% | 低 |
| 4 | 子代理 brief | ~5% | 低 |
| 5 | 工具输出压缩 | 0–6% | 中 |
| 6 | 模型路由 | 0–6% | 中 |
| — | 共享前缀/缓存预热/技能 stub | ≈0 | 不划算 |

**不要为了“看起来省”去动前缀、预热或技能 stub。**

## 2. 决策表

| 任务类型 | 任务前 | 执行中 | 交付前 |
| --- | --- | --- | --- |
| 长文/文档 | 大纲/章节索引；确认范围；判断峰谷 | 按节读；引用文件+行号；章节边界压缩 | 只给 diff/变更清单/未决问题 |
| IT/游戏 | glob/grep 定位；map/signatures | 只读行区间；日志压缩；子代理探索 | 只给 diff + 测试结果 |
| PPT | 定页数/故事线/模板/素材 | 脚本生成；素材落盘 | 只给文件路径+页数+摘要 |
| 调研 | 问题清单；来源列表 | 子代理并行取证；笔记落文件 | 只给结论+引用+未决问题 |

## 3. 压缩矩阵

| 内容 | 允许 | 手段 | 可逆 |
| --- | --- | --- | --- |
| 测试/构建日志 | ✅ | 失败用例、错误行、栈顶/栈底 | 必须 |
| JSON/API | ✅ | 结构摘要、数组采样、字段裁剪 | 必须 |
| git/docker/kubectl | ✅ | 按命令模板过滤 | 必须 |
| 源代码 | ❌ | 只能 map/signatures/lines | — |
| 文档正文/合同/标书 | ❌ | 只能分段读、diff 改 | — |
| 对话历史 | ⚠️ | 只用 DSH 原生 compaction | harness |
| 技能说明 | ⚠️ | 只做渐进披露 | — |
| 交付物 | ❌ | 不压，长度是产品 | — |

**判断：删掉一个词会不会改变事实、法律或代码语义？会，就不许压。**

## 4. 冲突与优先级

```
正确性 > 省 token
DSH 原生 compaction/spill > 自定义压缩
一段内容只允许一个压缩器
能换读取模式就不做文本压缩
能落文件就不塞对话
能拆子代理就不主线程硬扛
缓存命中率下降 >5 个百分点 → 回滚
```

## 5. 预算

| 项 | 上限 |
| --- | --- |
| 本技能 SKILL.md | ≤120 行 / ≤3KB（约 900 tokens） |
| 单个 reference | ≤8KB |
| 子代理返回 | ≤1500 tokens |
| 单次 squeeze | 只处理当前工具输出，不改写历史 |
| 注入规则 | 不写 always-on 长规则 |

`plan` 的上下文提醒来自本机最近会话的 `session_projcache`，可能不是当前会话，只作量级参考；准确值以 DSH 状态栏/当前会话为准。

## 6. 关闭开关

- `#cost-off`：本任务不启用任何压缩/裁剪。
- `#no-squeeze`：只关压缩。
- `#no-brief`：不强制子代理 brief。
- 环境变量 `TOKEN_BUDGET=off`：全局关闭。

## 7. 失败模式

| 现象 | 处理 |
| --- | --- |
| 压缩后找不到关键信息 | `retrieve <id>` 取原文；下次提高 level 或跳过压缩 |
| 模型反复重读同一文件 | 检查是否用了 map/signatures；把结论写到笔记 |
| 话变少导致多轮追问 | 输出保留“结论+证据+下一步”，不要只给结论 |
| 缓存命中率下降 | 检查是否改了前缀/频繁换模型/过早压缩 |
| A/B 省了但质量降 | 不算节省，回滚 |
| 技能自己太重 | 拆 reference，入口只留触发和红线 |
