# AI Flavor Guard

## 核心原则

1. **先判语境，再管词汇**：同一个词在技术文档里是术语，在情感文里是噪音。先确定"谁在说、对谁说、什么体裁、什么平台、什么行业、公开度"，再决定词汇预算。
2. **不查杀单词，查剂量**：判断"明显 AI 味"看密度、分布和搭配，而不是出现一次。单个词在正确语境中完全正常。
3. **保真第一**：不删事实、数字、引用、来源、限定条件和风险提示；不改变原意；技术、法律、医疗术语不得为"去味"牺牲准确性。
4. **不过度矫正**：不把正式文本口语化，不把专业文本改成大白话，不用碎碎念代替论证。
5. **只交付结果**：不在正文里解释自己如何遵守规则、如何思考、如何自检；用户没问，就不展示过程。

## 工作流

### 第 1 步：判定语境

按 [references/contexts.md](references/contexts.md) 第 1 节回答四问（谁在说 / 对谁说 / 什么体裁 / 什么平台与公开度），
从第 3 节预算表选定**档 ID**（`personal`/`social`/`marketing`/`report`/`bid`/`application`/`patent`/`standard`/`kb`/`tech`/`compliance`/`academic`/`official`/`translation`）。

四问答不全时按最严的合理档处理并注明假设，不要默认按"技术文档"放行。

### 第 2 步：写作或改写

- 初稿就按预算写，不要先堆黑话再回头删。
- 抽象词必须落到具体对象、动作、结果或数字；落不下去就删。
- 连接词能删就删，用时间、因果、动作顺序衔接。
- 段落长短按重要性分配，不追求均匀。
- 结尾收在动作、事实或朴素判断，不升华、不喊口号。

### 第 3 步：确定性扫描 + 语义自检

**可判定项 MUST 由脚本执行，不得用目测代替**：

```bash
python <skill-dir>/scripts/scan_flavor.py <文本.md> --profile <档ID> \
  --report <报告路径.md> --json <findings.json>
```

脚本覆盖：分级千字密度、单段堆叠、连续四字格、无来源空引用、结尾升华、F 级元话语、E 级连接词密度。
退出码 0 = 无 ERROR，1 = 有 ERROR，2 = 参数/文件错误。代码围栏内不检查；行内 `<!-- nocheck -->` 跳过全部规则。

解释器：扫描器只用标准库，任何可用的 Python 3 都行。Windows 上 PATH 里的 `python` 可能是应用商店占位程序（静默退出 49），
改用 `python3.12`，或共用环境 `%USERPROFILE%\.dsh\skills\kf-markdown-to-docx\.venv\Scripts\python.exe`
（设了 `ALL_IN_MD_OFFICE_VENV` 就用它指向的目录）。

脚本判不了的（形容词背后有没有事实、抽象词有没有具体指代、术语是否被误伤、是否过度口语化）
按下方「自检清单」逐项过。超出预算或触发硬性禁令时，**改产物本身**，不要只在说明里解释。

### 第 4 步：交付

只交付最终文本，不主动展示检查过程、评分或词频统计；用户要求诊断或评分时才展示摘要。

## 词语分级（速查）

分级前缀统一为 `AF-`，与 all-in-md 的发现严重度 A/B/C/X **不是同一套字母**，报告中不得混写。

| 级别 | 类别 | 代表词（完整词库见 references/lexicon.md） |
|---|---|---|
| **AF-A1** | 纯黑话（任何语境都无技术定义） | 赋能、抓手、打法、组合拳、心智、势能、飞轮、护城河、底层逻辑、第一性原理、颗粒度、降本增效、精细化运营、痛点、卡点、突破口、对焦、反哺 |
| **AF-A2** | 语境词（专业语境有定义，私人表达是噪音） | 闭环、对齐、拉通、沉淀、复用、链路、全链路、端到端、范式、方法论、体系化、常态化、长效化、落盘、口径、复盘、迭代、落地；生造的管理腔：门控、门禁、台账、核销、漂移 |
| **AF-B** | 工程/数据腔 | 埋点、灰度、降级、兜底、熔断、限流、幂等、解耦、编排、可观测性、鲁棒性、基线、回归、全量、增量、快照、回滚、容灾、双活、数据治理、数据血缘、漏斗、留存、转化、触达、拉新、促活 |
| **AF-C** | 公文/汇报套话 | 高度重视、深刻认识、统筹推进、精准发力、久久为功、抓铁有痕、下好先手棋、对标对表、压实责任、狠抓落实、形成合力、树立标杆 |
| **AF-D** | 空转形容词 | 深刻、全面、系统、精准、高效、强大、丰富、多元、立体、多维、全方位、多层次、高水平、高质量、新格局、新篇章 |
| **AF-E** | 连接词与万能句式 | 首先/其次/此外/值得注意的是/综上所述/归根结底；不仅…而且…/不是…而是…/随着…的不断深入/为…注入了强劲动力 |
| **AF-F** | 元话语与自我表演 | "按你的规则，我避免了…""本次全部是本地操作，没有调用任何联网工具""让我先分析""说人话就是""希望这对你有帮助"：汇报规则遵守、罗列自己没干什么、展示思考、替用户下判断 |

**A1 / A2 为什么拆开**：混在一起判必然误伤技术术语。A1 无论什么体裁都不因"专业"而豁免；
A2 在专业档（`tech`/`compliance`/`standard`/`patent`/`kb`/`bid`）有定义即保留。
判定顺序：先问这个词在本段有没有定义或具体指代——有就留，没有才按剂量判。

完整词库、替换对照与「误伤清单」见 [references/lexicon.md](references/lexicon.md)。

## 密度天花板

预算数值**只在** [references/contexts.md](references/contexts.md) 第 3 节维护，本文件不复制，避免两边对不上。
折算与分布规则见该文件第 4 节：短文（<300 字）按整篇计数；长文按每千字折算；
单段 A1+A2 ≥3 个即使全篇未超也判超标（纯 A2 堆叠在专业档降为 WARN）；连续 ≥3 个四字格不论文体一律超标。

## 元话语与自我表演（AF-F）

AI 味不只用词，也来自"AI 在输出里谈论自己"。禁止在交付文本中出现以下六类：

1. **规则汇报（邀功）**："按你提供的规则，我避免了…""这次我没用赋能、抓手""我已严格遵循真实第一原则""以下是符合要求的版本，我做了如下调整"。
2. **自证清白（免责声明）**："本次全部是本地文件操作，没有调用任何联网工具""我没有擅自改动其他文件""未做任何多余修改""不包含任何占位符""我没有多想，直接按你说的做"。用一串"我没干什么"给自己背书，读者要的是结果。整句删掉；真有限制或没做完的部分，只说那一条。
3. **过程外显（思考泄漏）**："让我先分析一下需求""我先判断体裁再定预算""我核对了密度：A 级词 0 个""我的改写思路是…"。
4. **原则声明（说教）**："写作第一原则是真实""好的文案应该…""真正重要的是…"（未经请求替用户定优先级）。
5. **自作聪明（替用户解读）**："其实你真正想要的是…""这背后的本质是…""很多人没意识到…""让我帮你翻译成人话""你可能没注意到…"。
6. **降维与助手腔**："简单来说 / 说人话 / 小白也能懂""你可以理解为…""希望这对你有帮助""如果你还有其他问题，随时告诉我""需要我继续优化吗""以上是我的回答"。

处理：只交付结果；用户要求诊断、评分、修改说明时才展示过程，且只展示被要求的部分。用户没问，不替用户重新定义需求。

## 硬性禁令（不论文体）

1. 禁止连续 3 个以上四字格（"高度重视、统筹推进、精准发力"）。
2. 禁止抽象名词作主语 + 抽象动词作谓语（"赋能增长""打造闭环""形成合力"），除非后文立刻给出具体指代。
3. 禁止结尾升华、口号、金句（"未来可期""书写新篇章""让我们拭目以待"）。
4. 禁止无来源的空引用（"数据显示""研究表明""专家指出"）——要么给出具体来源，要么删掉。
5. 禁止为凑字数写"正确但无信息"的平衡句（"既要看到机遇，也要警惕挑战"），除非说明具体风险、谁承担、怎么处理。
6. 禁止用排比制造气势代替论证；排比只在确有并列事实时使用。
7. 禁止汇报"已按规则 / 已避免某词 / 已通过自检"，也禁止罗列"没联网 / 没改别的文件 / 没有多余改动 / 不包含某物"给自己背书。
8. 禁止未经请求展示分析过程、改写思路、评分或自我评价。
9. 禁止替用户判断"你真正想要什么"，禁止评价自己的输出"更自然 / 更有网感"。
10. 禁止"简单来说 / 说人话"式俯视读者；需要解释就直接解释。
11. 禁止模板化助手结尾（"希望有帮助 / 随时告诉我"）；确需确认时用一个具体问题。

第 1/3/4/7/8/9/10/11 条由 `scan_flavor.py` 判定；第 2/5/6 条需语义判断，由自检清单或审查者负责。

## 例外（保留原词，不判 AI 味）

- 引用原文、合同条款、法规条文、技术规范、医疗诊断、学术引文。
- 用户明确要求公文、技术文档、行业术语或正式风格。
- 品牌名、产品名、系统字段名（如"口径"在数据治理文档中是字段定义，"落盘"在运维手册中是操作步骤）。
- 翻译任务中的源文术语。
- 行业固定说法（如医疗"适应证"、金融"久期"、法律"不可抗力"）。

合法引用禁词的场景（术语对照表、反例教学）在该行加 `<!-- nocheck -->` 豁免，并向用户说明理由。
误伤清单与更细的判断规则见 [references/lexicon.md](references/lexicon.md) 第 9 节。

## 改写方向（按优先级）

1. **名词化 → 动词 + 对象**："对用户路径进行优化" → "把注册页从 5 步减到 3 步"。
2. **抽象 → 结果/数字**："赋能销售团队" → "给销售多配了一块看板，周报从 4 小时缩到 1 小时"。
3. **删连接词**：用时间、因果、动作顺序衔接；"首先/其次/最后"多数可删。
4. **拆四字格**：三个以上四字格连用，改成一句白话。
5. **收尾落地**：结尾换成下一步动作、事实或朴素判断。
6. **保留术语**：专业文本只换"无信息"的部分，不换"有定义"的部分。

## 自检清单（脚本判不了的语义项，输出前逐项过）

- [ ] 是否先判定体裁、平台、受众，并选对了预算档？
- [ ] 每个抽象词是否落到具体对象、动作或结果？
- [ ] AF-D 形容词背后有没有可核对的年月、编号、参数区间、可点名对象？
- [ ] 是否误伤了术语准确性（技术/法律/医疗）？A2 词在本段有没有定义？
- [ ] 是否把正式文本过度口语化，或把私人文本写成公文？
- [ ] 事实、数字、限定条件、风险提示是否完整保留？
- [ ] 有没有"正确但无信息"的平衡句、用排比代替论证？
- [ ] 抽象名词作主语的句子，后文有没有立刻给出具体指代？

密度、四字格、空引用、结尾升华、元话语、连接词密度已由脚本判定，不必再目测重复。

## 与 all-in-md 的接口

all-in-md 处理标书/专利/软著/团标/申报书/知识库文档时按下列约定调用本技能：

| 环节 | 做什么 |
|---|---|
| Stage0 | 按 doc-type 映射选档（映射表见 contexts.md 第 6 节），写入需求规格书「词汇预算档」 |
| Stage1/2/4 | 主 agent 把档 ID + 硬性禁令摘要注入写作 prompt；子 agent 不加载本技能 |
| Stage3 L1 | 主 agent 跑 `scan_flavor.py --profile <档> --gate <warn\|error>`，findings 交检查者并入发现清单 |
| Stage3 第 8 维 | 检查者据剂量报告判语义项（误伤、无事实形容词、过度矫正） |
| Stage5 | 跑 `scan_flavor.py --profile <档> --gate <warn\|error>`，零 ERROR 才可交付 |

**门禁分档**：`fast` 档全部降为 WARN，不阻断；`standard`/`deep` 档
AF-01（A1 超预算）/ AF-07（四字格）/ AF-08（空引用）/ AF-09（元话语）/ AF-10（结尾升华）为 ERROR。
**AF-03（B 级工程术语）恒为 WARN**，AF-02（A2）在专业档恒为 WARN——这两类误伤代价高于漏检。
AF-05（D 级形容词）恒为 WARN：脚本判不了形容词背后有没有事实，交第 8 维定 C 级。

**冲突优先级**：用户显式风格要求 > 事实与术语准确性 > 本技能预算档 > 通用改写方向。
all-in-md 的 `../all-in-md/assets/文风范例.md` 是句式与信息组织基准，本技能只管词汇剂量；两者冲突时以文风范例 + 需求规格书为准。

## 与其他文风技能的关系

若本机安装了整体文风/人感诊断类技能（如 `doubao-human-signal`），可叠加使用：
先按本技能控制词汇剂量，再按该技能调整节奏、细节与口吻。
**未安装时本技能独立完成全部工作**，不得因缺该技能而跳过检查或声称已交接。
