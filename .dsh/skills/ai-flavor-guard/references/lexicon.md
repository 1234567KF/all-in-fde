## 1. 用法说明

- 词库用于**判断剂量**，不是机械查杀。先看语境（见 `contexts.md`），再决定这个词该不该留。
- 判断口诀：这个词能不能换成具体动作、对象或数字？删掉后信息有没有损失？这个体裁的读者会不会这么说？
- 同一个词在不同语境中的判定不同，例："落盘"在运维手册里是标准操作，在情感文里是噪音；"口径"在数据治理文档里是字段定义，在朋友圈里是黑话。
- **本文件是词库的唯一真相源**；预算数值在 `contexts.md` 第 3 节，本文件不复制数值。
- 分级前缀 `AF-` 用于与 all-in-md 的发现严重度 A/B/C/X 区分，两套字母含义不同。
- 确定性扫描由 `../scripts/scan_flavor.py` 执行，词表与该脚本的 `LEXICON` 保持同源；
  改词表时 MUST 同步改脚本，否则扫描结果与规则不一致。

## 2. AF-A1：纯黑话

任何语境都没有技术定义，只用来制造气势。**不因"专业文档"而豁免**，所有档位预算见 `contexts.md`。

### 2.1 核心词与替换方向

| 词 | 原义 | 非专业语境的替换方向 |
|---|---|---|
| 赋能 | 提供能力/资源 | 给谁配了什么、开了什么权限、教了什么 |
| 抓手 | 着力点 | 具体项目、具体动作 |
| 颗粒度 | 细化程度 | 细到什么程度、精确到哪一级 |
| 打法 | 策略 | 做法、办法 |
| 组合拳 | 多项措施 | 几个措施一起上 |
| 心智 | 认知 | 印象、认知、习惯 |
| 势能 | 势 | 优势、势头 |
| 飞轮 | 正循环 | 越转越顺的循环 |
| 护城河 | 竞争壁垒 | 竞争优势、别人抢不走的东西 |
| 底层逻辑 | 根本原因 | 真正的原因、根子上的问题 |
| 第一性原理 | 基础事实 | 最基本的事实、前提 |
| 降本增效 | 省钱提效 | 省了多少、快了多少 |
| 精细化运营 | 精细运营 | 具体做了什么运营动作 |

### 2.2 扩展词表

- 名词类：生态位、壁垒、水位、水位线、卡点、堵点、痛点、痒点、爆点、基本盘、工具箱、路线图、责任田、落脚点、着力点、切入点、突破口、场域、锚点
- 动词类：对焦、反哺、穿透
- 评价类：势能、动能、杠杆、组合拳、打法、心智

### 2.3 使用边界

- A1 词在**内部黑话圈**（互联网公司内部沟通）可以少量使用，但对外文案、跨行业沟通、个人表达、标书、专利、标准中应替换。
- 同一段出现 2 个以上 A1 词，基本可以判定为 AI 味或黑话腔。

## 3. AF-A2：语境词

在技术/数据/运维语境里有明确定义，在私人表达里是噪音。**判定顺序：先问本段有没有定义或具体指代**——有就保留，没有才按剂量判。

### 3.1 核心词与替换方向

| 词 | 原义 | 非专业语境的替换方向 |
|---|---|---|
| 闭环 | 完整流程 | 从头到尾跑完、有了反馈、能验收 |
| 对齐 | 达成一致 | 商量一致、统一说法、确认过 |
| 拉通 / 拉齐 | 协同一致 | 把几方叫到一起、统一到同一个数 |
| 沉淀 | 积累留存 | 积累下来、存档、写成文档 |
| 复用 | 再次使用 | 再用一次、接着用 |
| 链路 | 流程环节 | 流程、环节、上下游 |
| 全链路 / 端到端 | 全流程 | 从开始到结束、整个流程 |
| 范式 | 模式 | 做法、模式 |
| 方法论 | 方法体系 | 方法、步骤 |
| 体系化 | 系统化 | 成体系、配套起来 |
| 常态化 | 长期化 | 一直做、固定下来 |
| 长效化 | 长期有效 | 长期有用 |
| 落盘 | 写入磁盘 | 保存、写入、存档 |
| 口径 | 计算定义 / 统一说法 | 数据语境写"计算定义、按什么算"；管理语境写"标准、要求" |

### 3.2 扩展词表

打磨、拆解、收敛、透传、打通、复盘、迭代、落地、生态

### 3.3 生造的管理腔

把别的行业的现成词硬搬到文档流程里，读者要先猜一遍才知道指什么。这类词一律换成日常说法：

| 词 | 被借用的原义 | 该写成什么 |
|---|---|---|
| 门控 | 电路里的门控信号 | 校验、规则、放行条件 |
| 门禁 | 大楼的门禁系统 | 检查、放行规则、能不能过 |
| 台账 | 会计的明细账簿 | 清单、记录表、对照表 |
| 核销 | 财务的坏账核销 | 逐条确认、勾掉、标记已修复 |
| 漂移 | 仪器的零点漂移 | 不一致、对不上、跑偏 |

判断标准很简单：这个词在本行业有公认定义吗？没有就换。有定义但用错了行业（把"核销"用在检查清单上），同样换。

### 3.4 使用边界

- 专业档（`tech`/`compliance`/`standard`/`patent`/`kb`/`bid`）中有定义即保留，脚本只报 WARN，不阻断交付。
- 非专业档中按 `contexts.md` 预算计入密度；无定义的"打造闭环""形成对齐"一律替换。

## 4. AF-B：工程/数据腔

### 4.1 词表

埋点、灰度、降级、兜底、熔断、限流、幂等、解耦、耦合、编排、调度、吞吐、时延、可观测性、鲁棒性、健壮性、可扩展性、基线、基准、回归、冒烟、全量、增量、快照、回滚、容灾、双活、多活、灾备、数据治理、数据资产、数据血缘、元数据、主数据、标签体系、画像、漏斗、留存、转化、触达、投放、拉新、促活、召回

### 4.2 使用边界

- 出现在**技术文档、运维手册、数据文档、产品需求文档、标书、专利、标准**中：标准术语，正常使用。
- 出现在**面向大众的文案、情感文、生活分享、个人邮件**中：AI 味明显，应换成普通人能懂的说法（"灰度" → "先给小部分人用"；"降级" → "功能先用简化版顶上"；"兜底" → "出问题时有个保底方案"）。
- 脚本对 B 级**恒报 WARN，不阻断交付**：误伤术语的代价高于漏检。

## 5. AF-C：公文/汇报套话

高度重视、深刻认识、准确把握、全面落实、统筹推进、协同发力、多点发力、精准发力、持续发力、久久为功、驰而不息、抓铁有痕、踏石留印、钉钉子精神、下好先手棋、打好主动仗、守正创新、问题导向、目标导向、结果导向、底线思维、系统观念、全局视野、战略高度、政治站位、对标对表、压实责任、狠抓落实、闭环管理、形成合力、凝聚共识、营造氛围、树立标杆、打造样板

### 使用边界

- 在**真实公文、政府文件、党建材料**中属于语体要求，允许使用，但要求每句都有实际内容支撑。
- 在**普通工作汇报、邮件、产品文案、社媒**中出现，即为典型的"官话/AI 味"，应替换成具体事实。
- 在**标书、专利、标准、知识库**中预算为 0；**申报书**留 ≤1 且须有事实（语体惯性）。
- 连续 3 个以上 C 级四字格连用，无论什么文体都判为明显 AI 味。

## 6. AF-D：空转形容词

深刻、全面、系统、深入、持续、有效、显著、大幅、精准、高效、便捷、智能、强大、丰富、多元、立体、多维、全方位、多层次、宽领域、深层次、高水平、高质量、高标准、严要求、新高度、新境界、新格局、新篇章、新动能、新引擎、新抓手、新载体、新局面

### 使用边界

- 形容词本身不是问题，**没有对应事实**才是问题。"显著提升"要么给数字，要么删掉。
- 一段里连续出现 2 个以上无事实支撑的 D 级词，视为 AI 味。
- 脚本判不了形容词背后有没有事实，因此**恒报 WARN**；由审查者判是否构成 C 级发现。

## 7. AF-E：连接词与万能句式

### 7.1 连接词

首先、其次、再次、最后、此外、同时、与此同时、值得注意的是、值得一提的是、需要指出的是、不可否认的是、毋庸置疑、显而易见、综上所述、总而言之、归根结底、说到底、换言之、简而言之、换句话说、从某种意义上说、从这个角度看、由此可见、不难看出、某种程度上、一定程度上、总体而言、概而言之

判断：单个词不是问题；千字超过 8 个且分布均匀，基本可判 AI 味；每段都靠连接词推进，说明结构在替代思考。

### 7.2 万能句式

- 不仅…而且…、既…又…、一方面…另一方面…、不是…而是…、与其说…不如说…
- 随着…的不断深入、在…的背景下、以…为抓手、以…为突破口、围绕…展开、聚焦…发力、锚定…目标
- 为…提供了有力支撑、为…奠定了坚实基础、为…注入了强劲动力、标志着…迈上新台阶、实现了…新突破、取得了…新成效、展现出…新气象
- 结尾：未来可期、值得期待、让我们拭目以待、必将、势必将、书写新篇章、开启新征程、行稳致远

判断："不是 A 而是 B"一篇长文中只能少量使用；连续出现 2 次以上，像模型在制造洞察。结尾金句单独成段，基本可判 AI 味。

## 8. 通用替换对照

| 原表达 | 问题 | 替换方向 |
|---|---|---|
| 围绕 X 展开 | 空转 | 做了 X、X 是怎么做的 |
| 在 X 背景下 | 空转 | 因为 X、X 之后 |
| 为 X 提供了有力支撑 | 空转 | 帮 X 解决了什么具体问题 |
| 标志着 X 迈上新台阶 | 空转 | X 这次做到了什么、比以前多了什么 |
| 实现了 X 新突破 | 空转 | 第一次做到什么、指标从多少到多少 |
| 对 X 进行优化 | 名词化 | 把 X 从 A 改成 B |
| 提升 X 的能力 | 抽象 | 具体能力是什么、现在能做什么 |
| 打造 X 闭环 | 空转 | 从 A 到 B 都跑通了 |
| 形成 X 合力 | 空转 | 哪几方各自做了什么 |
| 未来可期 | 升华 | 下一步先做什么 |

## 9. 误伤清单（不要查杀）

以下情况出现"敏感词"是正常的，不要改：

1. **技术/运维/安防文档**：灰度、降级、兜底、熔断、幂等、落盘、埋点、基线、回归、快照、回滚、双活、灾备；门禁系统、门控设备是本义与产品名。
2. **数据/财务文档**：口径、粒度、留存、转化、漏斗、触达、投放；财务与资产管理里的台账、核销是本义，保留。
3. **公文/政府文件**：统筹推进、压实责任、对标对表（语体要求，但需有实际内容）。
4. **合同/法规/医疗/学术**：引用原文、条款、诊断、术语（如"适应证""久期""不可抗力"）。
5. **用户明确要求**：用户指定要公文腔、官方口径、行业黑话、品牌 slogan。
6. **翻译**：源文本身的术语和风格，不为去味改动。
7. **品牌与产品名**：包含敏感词的官方名称（如"XX 赋能计划"）不能改。
8. **引号内的原话**：转述他人原话时保留原词，可在引号外正常表述。

判断顺序：先问"这个词在本语境有没有定义/指代"；有定义就保留，没定义就替换。
合法引用禁词的行（术语对照表、反例教学）加 `<!-- nocheck -->` 豁免，脚本会跳过该行全部规则。

## 10. AF-F：元话语与自我表演

这不是词汇问题，而是"叙述对象错了"：文本在谈 AI 自己，而不是内容本身。它比任何单个黑话词都更像 AI。

### 10.1 六类清单

| 类别 | 典型表达 | 为什么是 AI 味 | 处理 |
|---|---|---|---|
| 规则汇报 | "按照你提供的规则，我…""这次我没有使用…""我已严格遵循…""以下是符合要求的版本，我做了如下调整" | 把合规当成需要展示的成果；读者不关心过程 | 直接给结果；用户要求改稿说明时再列 |
| 自证清白 | "本次全部是本地操作，没有调用任何联网工具""我没有擅自改动其他文件""未做任何多余修改""不包含任何占位符""我没有多想，直接按你说的做" | 用一串"我没干什么"给自己背书；读者要的是结果，不是免责声明 | 整句删掉。真有限制或没做完的部分，只说那一条，不铺陈自己守了什么规矩 |
| 过程外显 | "让我先分析一下""我先判断体裁""我核对了密度""我的改写思路是" | 思考过程对读者无信息价值 | 删掉"我怎么做的"，只留"做了什么" |
| 原则声明 | "写作第一原则是真实""好的文案应该…""真正重要的是…" | 说教；替用户定优先级 | 除非用户问原因，不声明原则 |
| 自作聪明 | "其实你真正想要的是…""这背后的本质是…""很多人没意识到…""让我帮你翻译成人话""你可能没注意到…" | 未经邀请的洞察、替用户定义需求 | 只回答被问的问题 |
| 降维/助手腔 | "简单来说""说人话就是""小白也能懂""你可以理解为…""希望这对你有帮助""随时告诉我""需要我继续优化吗""以上是我的回答" | 俯视读者 + 模板化收尾 | 直接说完；确需确认时用一个具体问题 |

### 10.2 判定口诀

- 这段话是在谈"内容"，还是在谈"我"？
- 删掉这句，读者得到的信息有没有减少？
- 用户有没有要求我说明过程、评分或修改理由？

三问里只要出现"在谈我"且"信息没减少"，就删。

补一条硬性规则：**罗列"我没做什么"的句子一律删**。没联网、没改别的文件、没加多余内容、没有占位符——这些是默认状态，不是成果。只有确实存在的限制、确实没做完的部分才值得写，而且只写那一条。

### 10.3 例外

- 用户明确要求诊断、评分、修改说明、思路讲解：按要求的范围输出，且只输出被要求的部分。
- 协作场景确实需要交代改动（如改合同条款）：用"改了哪一条"的清单，不写"我遵循了…原则"。
- 第一人称创作内容（故事、个人陈述）：文中的"我"是内容角色，不是 AI 自己，不受此限。
- **工作稿不受此限**：all-in-md 的 `.all-in-md-out/` 检查报告、改动清单、台账属于过程产物，
  允许写"已修复/未修复/核销"；AF-F 只约束**交付正文**。
