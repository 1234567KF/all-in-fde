# 交付与回流（delivery）

交钥匙 + 记一条返工。把「能跑」变成「换台机器照文档也能跑」，并把这次的坑变成下次的门。

## 什么时候用

验收通过，准备交付或归档。

## 怎么做

1. **交付三件套**：README（装与起）、部署说明、回滚说明。打包压缩的临时件放 `.fde-tmp/`，交付物本身放交付目录。只照 README 能起来才算，不靠「我记得」。
2. **干净目录复跑**（E7）：复制到新目录（不带依赖、不带数据库），按 README 装与起 → 冒烟 → 回滚验证。任何一步失败即 E7 红，退路是补 README。
3. **内网坐标扫描**：交付物里无内网地址、账号、令牌路径。用现成扫描器或自写小脚本；没有脚本就人工按 `192.168.`、`10.`、`localhost:`、`token` 逐项搜。三态退出码，SKIP 不等于通过。
4. **差异清单**：与客户口径的差异、挂起项、已知问题，逐条含复现方式。
5. **写证据**：`evidence/E7-*.json`。
6. **retro**：复盘「哪条证据事后被证明是假的」「哪个坑下次可以挡」，变成一条判据或一道门，写进 `retro.md`。没有可执行改动写「无」，不写感想。`shortcut:` 注释里欠的账汇总进债务台账。

## 什么算完

- 干净目录 README 复跑成功；
- 回滚可复现；
- 无未登记的 FAIL 或已知问题；
- retro 至少一条可执行改动（或写「无」）。

## 常见错

- **在自己机器上复跑**：环境早被改过，不算干净。必须新目录/新容器。
- **README 缺步骤但「我记得」**：所有步骤写进文档，机器比记忆可靠。
- **把 SKIP 当通过**：SKIP 必须写原因与补救，且该门不算过。
- **retro 写感想**：只写能落成判据或门的东西。
