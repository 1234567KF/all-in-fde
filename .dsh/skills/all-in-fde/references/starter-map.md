# 脚手架对照表（starter-map）

起架之后写票、派活的对照表。脚手架的具体坐标从 `.fde/starter.json` 读，这里只讲结构。

## 目录与职责

| 路径 | 放什么 | 谁产出 |
| --- | --- | --- |
| `apps/api/src/modules/<name>/` | 业务模块：路由、服务、查询、测试 | 模块生成器 |
| `apps/api/drizzle/` | 迁移与快照 | 生成器，序号必须连续 |
| `apps/web/src/pages/<name>/` | 页面与页面内组件 | 按 S7 手写 |
| `packages/shared/src/<name>.ts` | Zod 契约与枚举（唯一真源） | 手写，两端共用 |
| `packages/ui/src/components/ui/` | 白盒组件 | 现成，不重写 |
| `web-apps.json` | 多端注册表 | 脚手架命令写入 |

## 哪类改动进哪一层

| 改动 | 落点 | 走生成器 |
| --- | --- | --- |
| 新业务模块（表 + 接口 + 页面） | `apps/api` + `packages/shared` + `apps/web` | 是 |
| 只改页面或交互 | `apps/web` | 否 |
| 改契约字段 | `packages/shared`，先改契约再改两端 | 否，但两端同步 |
| 改表结构 | `schema` + 迁移 | 是（序号连续，禁并发生成） |
| 新增端 | `web-apps.json` | 是（脚手架多端命令） |

## 两处约定（技能内部先说清，避免两套 SOP 打架）

1. **三级真源**：采集表（S0–S15）是**需求输入层**；PRD 是**业务事实层**；`spec/<module>.md` 是**模块实施层**。起架后把 spec 映射成模块生成器的输入，不并行维护多套。
2. **模块实现归谁**：all-in-fde 管票与门禁；票的「命令」列写模块生成器；模块内部实现交给脚手架自带的领域技能。一张票只归一个执行者。

## 门禁分工

| 门禁 | 覆盖 | 归属 |
| --- | --- | --- |
| typecheck / lint | 类型与代码规范 | 脚手架 |
| migrate:check | schema 与迁移同步 | 脚手架 |
| arch:check | 分层、懒加载、单文件行数 | 脚手架 |
| test | 单元与接口 | 脚手架 + 本技能 |
| E5 数据断言 | 金额、状态、关联一致性 | 本技能 |

脚手架的门禁管「结构对不对」，本技能的断言管「算得对不对」，两层都要过。

## 禁区清单（Worker 默认排除，不许改）

以下锚点和标记由生成器 / 架构门禁维护，Worker 清理注释或重构时**必须跳过**，否则打断生成器或基线：

| 模式 | 用途 | 后果 |
| --- | --- | --- |
| `[gen:module:*]` | 模块生成器注册锚点 | 删掉后 gen:module 找不到注入位置 |
| `#region module:*` / `#endregion` | IDE 折叠区 + 生成器边界 | 删掉后代码块归属丢失 |
| `feature:*` | 功能开关注册 | 删掉后特性无法启用/禁用 |
| `LONG_FILE_RATCHET` | 单文件行数基线 | 改小后 arch-check 误报 |
| `// @generated` / `/* auto-generated */` | 自动生成标记 | 删掉后 lint 把生成代码当手写代码审 |

**授权范围默认排除以上所有**。票面「可改」列表里即使包含对应文件，也要保留这些标记。
