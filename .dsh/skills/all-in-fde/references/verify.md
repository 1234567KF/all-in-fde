# 验收（verify）

跑完不代表能用。这一步把「测试全绿」变成「人能用、数据对」。QA（`fde-verify` 子代理）+ 人一起做。

## 什么时候用

全部票 done，进入交付前的最终验收。

## 怎么做

1. **独立复核**：干净上下文的复核子代理，只读票 + Spec 片段 + 证据，只审不改，重跑验收谓词、核对防假绿三条。触碰共享契约/权限/认证的票必须复核，其余抽三分之一。
2. **冷启动清单**（不依赖测试结果，逐项记证据）：
   1. 删库重置 2. 后端冷启动，种子账号数对 3. 前端启动，端口不漂 4. 逐角色登录落对页面 5. 禁用账号被拒 / 需改密弹页 6. 核心旅程走通 7. 异常分支（403/409/空态/超长）8. 控制台无 A 类错 9. 验收卡点选 10. E2E 真实模式
3. **E2E**：阻塞四类 + 主链，无头跑门禁；核心用例两模式（无头/有头）结果一致才过 parity。视觉基线只由有头产生，证据记 `e2e.mode`、`browser.version`、`viewport`、`reducedMotion`。失败截图与 trace 落 `.fde-tmp/`，不落 `.fde/`。
4. **验收卡**：3–5 项，每项指到可打开的东西（文件行号 / 页面路由 / 截图 / 测试名），人点选；固定一项「抽 1–2 笔数据手工验算」。
5. **写证据**：`evidence/E6-<卡号>.json`，由卡片工具落盘。

## 分两段派：先跑后判

验收混着两种活：**跑**（执行命令、看红绿）和**判**（证据能不能证明验收、数据对不对）。一个档只能取高的，等于全程高配。所以拆两段派：

| 段 | 干什么 | 档 |
| --- | --- | --- |
| qa-run | 冷启动十步、E2E 阻塞四类、收截图与退出码 | `low` |
| qa-judge | 只读证据：验收谓词是否真被证明、数据断言是否成立、有没有假绿 | `high` |

**升 `max` 的确切条件**（满足任一）：

1. 本次判定涉及金额、权限、并发任一信号；
2. `qa-run` 报过失败，且失败点落在数据或状态上（不是环境、不是端口）；
3. 同一张票已是第二次验收。

**降 `off` 的确切条件**：只重跑一条命令复核退出码，没有任何判定动作。

两段之间**不共享上下文**：judge 只拿证据文件与票，不拿 run 的推理过程，避免先入为主——这就是「独立复核」的字面意思。
## 什么算完

- 冷启动十步全过；
- 验收卡无「有问题」；
- E2E 阻塞四类 + 主链全绿，parity 无 diff；
- 卡上「数据手工验算」一项通过。

## 常见错

- **没删库就用老数据验收**：冷启动第 1 步是删库，跳过它，全绿是假的。
- **E2E 只跑 mock**：交付前必须真实后端跑一遍，只跑 mock 不算绿。
- **拿手动截图冒充自动化证据**：截图是人卡证据（card），自动化证据必须来自脚本（script）。
- **验收卡写成「页面正常」**：不可判定的项不算项，退回改。
