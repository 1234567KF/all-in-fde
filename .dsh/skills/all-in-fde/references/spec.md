# 校准（spec）

把 brief 摊成需求采集表，人审定后出 PRD 分卷与原型。这是全流程的事实层，后面的票、代码、验收都从这里取。

## 什么时候用

`brief.md` 齐但还没有采集表 / PRD。

## 怎么做

1. **填表**：按 `assets/需求采集表-空白模板.xlsx` 的 16 张表填。轻量档只填 S0/S1/S3/S5/S7/S11，其余在 S15 记「本档不适用 + 理由」。
2. **填表铁律**：
   - S0 原文一字不改；客户没说的写「待确认」，AI 推断只进 S13「AI建议方案」，不许写进事实列。
   - 编号发布后不复用（`REQ-`、`AC-`、`BR-`、`EB-`、`F-`、`E`、`ST-`）。
   - 每行能回指来源；指不到就是编的。
   - AC 必须带数据断言（金额到分、汇总=明细合计、状态字段值），只写「操作成功」的 AC 不算数。
3. **人审五页**：只请人看 S0 原话、S3 角色、S5 主链、S7 页面、S13 疑问，出决策卡（≤3 项/轮）。审定痕迹 = 五页「客户核验」列全为已核验。
4. **出 PRD 分卷**：按 15 卷切法（00a/00b/01/02/03–07/08a–08b/09/10/11/12），00a 第一节写信息优先级（业务规则以 PRD 为准，原型冲突以 PRD 为准），每卷二级标题写来源行 `> 来源：S7 r12；AC-C01`。轻量档压成三卷（概览 / 页面 / 验收）。
5. **出原型**（UI 项目）：每个页面顶部写注释 `<!-- 页面ID: xxx | 来源: S7 rN -->`。字段、按钮、空态与 S7 逐项对应，原型不发明字段。
6. **回写**：生成中发现的缺口记 S15，新问题记 S13，人拍板记 S14 并回写受影响行。
7. **草稿**：成稿前的中间稿、导出的临时表格放 `.fde-tmp/drafts/`，成稿才写进 `docs/specs/` 与 `prototype/`。

## 什么算完（E4 四查，人工做，脚本可辅助）

四项都是「列集合、求差集」，差集为空才算过：

- 表齐不齐（按档；轻量档缺的表必须在 S15 有「不适用 + 理由」）；
- S15 每行「覆盖结论」无未覆盖；
- 抽 PRD 全文的编号与表内编号求差，差集为空；
- 原型页面 ID 与 S7 页面 ID 求差，差集为空。

## 常见错

- **AI 把推断写进事实列**：推断只进 S13，事实列留「待确认」。
- **表填完没人审就生成 PRD**：A1 的出口判据是审定痕迹，不是「表生成出来了」。
- **PRD 与表各写一套**：PRD 只引用编号，再抄一遍字段表就是第二份真相。
- **原型照搬了需求稿的 DOM 和色值**：只取字段与流程语义，UI 走设计系统的语义 token。
