# 收活（intake）

把「一段话」变成一页 brief + 采集表 S0 的原文。本步只定「做什么、给谁、不做什么」，不写字段、不写界面。

## 什么时候用

扫描发现没有 `.fde/brief.md`；或用户新开一个需求。

## 怎么做

1. **收原文**：把用户的话一字不改贴进采集表 S0 的「内容原文」列，一句可拆多行，不许润色、不许合并。附 PRD/原型/截图时，登记文件名与存放位置到 S0。
2. **三问**（只问带默认值的选择题，不开放式盘问）：
   - 给谁用？（默认：单人 / 内部团队 / 外部客户，选一个）
   - 输入输出是什么？（一句话）
   - 不做什么？（至少一条，写不出就问「你最不想它变成什么样」）
3. **写 `.fde/brief.md`**，五节：做什么 / 谁用 / 输入输出 / 不做什么 / 怎么算成功。每节 1–3 行，不许写字段。
4. **写证据**：`evidence/E1-*.json`（E1 是检查项，记 `mode` 与 `summary`）。

## 什么算完

- `brief.md` 五节齐全，无 TBD；
- S0 至少一条原文，且是用户原话；
- 「不做什么」至少一条。

## 常见错

- **把原话“优化”成书面语**：S0 必须是原话，AI 的理解进 brief，两者分开。
- **开放式盘问**：一次问五个开放问题，人答不上来就卡住。改三问带默认值。
- **跳过 S0 直接写 brief**：没原文锚点，后面 S15 覆盖核对就无从对起。
- **brief 里塞字段**：字段属于采集表 S7/S8，写进 brief 就是第二份真相。
