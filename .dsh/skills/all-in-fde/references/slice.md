# 切片与派发（slice）

把 PRD + spec 切成一组票，标依赖、分波次、派执行者。**切片的依据是 PRD 与 spec 的整体技术方案**，不是采集表的行号。这是 Router 的核心活。

## 什么时候用

PRD + spec 已封版（E2.5 PASS），`tickets/` 为空。

## 怎么做

1. **读 PRD + spec**：先通读 PRD 全文（或 `prd/index.md`），再逐个读 `spec/<module>.md`。切片依据是模块的业务边界与技术依赖，不是采集表 S7 的行号。
2. **按模块+路径分组**：以 spec 里的业务模块为单位，一个 `REQ-` 起步；耦合的多个模块合成一票，一个模块复杂时拆成多票（列表 / 表单 / 审批），拆完仍是「能单独演示的一条竖切」。
   - **一票一条演示路径**是硬规则。判据：这张票做完，能否当着人从头点到尾？
   - **禁止批次票**：一张票同时含 3 个以上业务模块（例：溯源码 + 扫码明细 + 预警 + 公共查询）时，演示路径会被依赖卡住（扫码明细没有数据来源、预警没有告警来源），E5-1「验收谓词逐条有证据」也无法机械核对。宁可多开三张票。
2b. **宽重构例外（expand–contract）**：一次机械性改动（重命名列、替换共享类型、统一枚举值）爆炸半径覆盖全库、无法竖切成可演示路径时，不强套竖切，改按三段排票：
   - **expand**：新旧两种形态并存建票（加新列/新类型，旧的不删），单独一票；
   - **migrate**：按爆炸半径分批迁移调用点，一批一票，每票阻塞于 expand，旧形态仍在所以批批可保 `check` 绿；
   - **contract**：全部迁完后删旧形态一票，阻塞于所有 migrate 票。

   分批仍保不住绿的（如全局类型推断连锁失败）：各批共享一条集成分支，全部阻塞到最后一张「集成验证票」，绿只在验证票上承诺。此时「一票一演示路径」按 SKIP 记录在交付回执（理由：宽重构，验收谓词改为批次退出码 + 最终验证票），不算违规。

   宽重构票的授权范围要写明爆炸半径边界（哪些目录在本批、哪些在后续批），防止 Worker 顺手全量替换。
3. **定轨道**：`Base`（底座：账号、状态机、编号、共享组件）/ `Module`（业务）/ `QA`（验收）。
4. **排依赖与串并**：每票写「阻塞」与「串并」两列——阻塞管能不能开，串并管怎么开。
   - 必须串（🔗）：改同一张表/迁移、改共享契约、改注册标记
   - 可并（🔀）：纯页面切片、纯配置、纯文案、独立端
5. **分波次**：Wave 0 底座，之后按业务域分。≤5 票的项目不排波次，直接 `T-01..T-0N`。
6. **写票**：每票一个文件 `tickets/<票号>-<slug>.md`，字段如下：

```text
票号：W1-T03            （≤5 票的项目用 T-03）
标题：合同审批生效
轨道：Module
阻塞：W1-T01             （无则写「无」）
串并：🔀 并行
授权：业务方张三批准；可改 apps/web 与 packages/shared；不动契约字段；diff 超 200 行停下问
挂 REQ：REQ-C01
验收：AC-C01 / AC-C02
Spec：spec/contract.md#审批
命令：bun run gen:module --name contract   （命令名以 .fde/starter.json 的 moduleCmd 为准）
三阶段：① AI 首轮 ☐   ② 人走查 ☐   ③ QA 封卡 ☐
标签：#task=W1-T03       （Worker prompt 里带上，供 token-budget verify 关联）
交付回执：（做完填：Spec 路径、迁移号、接口/表摘要、下游提醒）
```

   **同步生成 brief**：写完票后立刻调 `node <token-budget>/scripts/brief.mjs --goal "<标题>" --inputs "spec/<module>.md,tickets/<票号>-<slug>.md" --out .fde-tmp/brief-<票号>.md`。brief 是 Worker 的第一输入，比裸 prompt 省 token（减少来回澄清）。

7. **排期问答**：人问「先做哪些 / 开几个 Agent」时，只回「立即可并行的票池」+「必须顺序推进的串联链」，不替人决定人数。

票面「Spec」与「交付回执」引用 spec 时，优先引章节锚点而非文件路径；spec 里的状态机、schema、类型定义这类决策性内容可以内联进票，实现细节和代码片段不要抄进票——会随实现过期。

## 什么算完

- 每票一上下文装得下（单票改动 ≤6 文件）、做完能演示、阻塞边真实；
- 依赖无环（`node scripts/check-tickets.mjs <票目录>` 退出 0；票少时也可画一张依赖表人工核对）；
- 每票验收谓词 3–5 条，且来自 S11 的 `AC-`；
- 票面纪律合规（`check-tickets.mjs` 会拦）：三阶段只用 ☑/☐、勾了①必须有交付回执、挂 REQ 超过 3 个前缀会被警告为批次票。

## 常见错

- **按功能模块横切**（建表一张、按钮一张）：每张都演示不了。判据：这张票做完能不能当着人点一遍。
- **批次票**：一张票塞 3–4 个模块，声称「一批做完」。实际后果是上下文撑爆、演示路径断、验收无法逐条核对；拆成三张票，每张一条路径。
- **把「相关」写成「阻塞」**：阻塞必须是真的先做才能开，否则会造出假串行。
- **AI 代勾②③**：只勾①，②③必须等人。
- **用第三态符号表示进度**：`◐` 会让「做完没做完」变糊；进度写进交付回执正文。
- **票里抄字段表**：字段在 S7，票只引用 `REQ-` 与验收谓词。
## 派发时定档

子代理的推理档由主控按票定，默认 `low`，按难度升。四档：`off` / `low` / `high` / `max`。

### 先算难度：五个信号，命中几个

从票的字段直接读，不靠感觉。每命中一个记 1 分：

| # | 信号 | 从哪看 | 命中条件 |
| --- | --- | --- | --- |
| S1 | 动共享契约 | 授权范围 / Spec | 改 `packages/shared`、改接口形状、加枚举值 |
| S2 | 动权限或审计 | 授权范围 / AC | 新增权限点、改数据可见范围、改审计留痕字段 |
| S3 | 动金额、计算或状态机 | 验收谓词 | 出现钱、税额、汇总、守恒、状态流转 |
| S4 | 动并发、幂等或事务 | 验收谓词 | 出现重复提交、重试、锁、唯一约束、跨表写 |
| S5 | 跨端或跨模块 ≥2 | 挂 REQ / 页面 ID | 一次要改两个端或两个域的代码 |

映射（先看失败次数，再看分数）：

| 情况 | 档 |
| --- | --- |
| 连续失败 2 次（不论分数） | `max` |
| 命中 ≥4 分 | `max` |
| 命中 2–3 分 | `high` |
| 命中 0–1 分 | `low` |
| 纯文案 / 配置 / 搬数据，且 S1–S5 全 0 | `off` |

算例：合同审批票——S1 不动契约 0、S2 动权限 1、S3 有状态流转 1、S4 无并发 0、S5 列表 + 详情两页 1，共 3 分 → `high`。同一批里的「合同列表文案调整」：五项全 0 → `off`。

**为什么这么定**：这五个信号正好对应「错了难发现」的四类——契约错是全局漂移，权限错是越权，金额错是账不平，并发错是偶发。返工成本高的地方才值得多想。

### 定档三条纪律

1. **先定档再派**，不要派出去发现不对再改。
2. **升档要写理由**：回执里记一行「档位 high，因为命中 S2/S3」——没有理由的升档视为拉满。
3. **降档只降展示层**：命中 S1/S2 任何一项，最低 `high`，不许降到 `low`。

### ponytail 档位联动（v0.5.0 新增）

推理档定了之后，Worker 加载 ponytail 时按以下映射选档位，不一律 full：

| 推理档 | ponytail 档 | 理由 |
| --- | --- | --- |
| `off` | `lite` | 纯文案/配置改动，不需要最小改动哲学，省 token |
| `low` / `high` | `full` | 常规实现，ponytail 默认行为刚好 |
| `max` | `ultra` | 高难票（金额/权限/并发），让 ponytail 反问需求合理性再动手 |

派发时在 subagent prompt 里写明：`加载 ponytail <档位>`。Worker 收到后执行 `/ponytail <档位>` 切换。
