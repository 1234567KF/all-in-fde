# IT/游戏开发 playbook

适用于代码实现、重构、接口设计、Unity/Unreal 脚本、数据分析脚本、部署配置。

## 1. 任务前：先定位，不读全仓

1. `glob` 看目录结构，`grep` 找入口/符号/错误关键字。
2. 对目标文件先读 `map`/`signatures`（函数名、导出、依赖），不读全文。
3. 列出“要改的文件 + 每个文件的改动点”。
4. 判断峰谷：大重构/批量生成放低谷；小修复可高峰做。

## 2. 读代码：按需分层

| 目的 | 读法 |
| --- | --- |
| 了解结构 | 目录树 + 文件头 + 导出列表 |
| 找调用点 | `grep` 符号名，读命中行上下文 |
| 改一个函数 | 只读该函数行区间 |
| 审查 | diff + 关键分支 + 测试 |

- 同一文件不重复整读；把结论写到 `notes.md`。
- 不把整文件贴进对话；引用 `文件:行号`。
- 不压缩源代码；压缩会破坏语法和语义。

## 3. 改代码：diff 优先

- 先给改动计划（文件、函数、风险），再动手。
- 输出 unified diff 或替换块；不重贴整个文件。
- 改完跑最小验证（单测/类型检查/启动）；日志用 `squeeze`。
- 测试日志只留失败用例、错误行、栈顶/栈底；通过用例折叠。

## 4. 探索与并行

- 大范围搜索、依赖分析、日志排查交给子代理。
- brief 写明：仓库根、目标符号、只读、返回 ≤1500 token、结果写文件。
- 子代理回报“文件:行号 + 结论”，不要把源码贴回主线程。

## 5. 模型/effort

- 默认 flash；机械改动低 effort。
- 架构、疑难、跨模块设计才升 pro/高 effort；先确认质量收益。
- 不在会话中途频繁换模型，避免缓存失效。

## 6. 交付

对话里只给：

1. 改动文件列表；
2. 关键 diff/摘要；
3. 测试命令与结果；
4. 风险/未覆盖项。

## 7. 验收清单

- [ ] 只改必要文件，未做无关重构
- [ ] 有最小验证，失败日志完整
- [ ] 没有把源码大段贴回对话
- [ ] 没有压缩源代码
- [ ] 有 `#task` 标签，便于 `verify`
