# all-in-fde 子代理预设

三个 DSH agent preset，用一份本地 bundle 装上。装上之后，主控会话可以把票派给独立的 Worker 与 QA 会话；没装时技能自动退回同屏执行。

## 三个预设

| 预设 id | 显示名 | 能做什么 | 刻意不给的工具 |
| --- | --- | --- | --- |
| `fde-lead` | FDE 主控 | 读写文件、跑命令、后台任务、todo、向人提问、web、加载技能、派子代理（只允许 `fde-worker` / `fde-qa`） | 无（它就是编排层） |
| `fde-worker` | FDE 逐单 | 读写文件、跑命令、搜索、后台任务、todo、加载技能（含 ponytail） | **没有向人提问**、没有派子代理、没有 web/schedule/goal——想提问只能写进报告 |
| `fde-qa` | FDE 验收 | 只读文件、跑命令（测试/E2E）、搜索、后台任务、加载技能、末尾向人提一张验收卡 | **不能写文件**（write/edit 关闭），不能派子代理 |

三条刻意的取舍：

1. **Worker 没有提问工具**：这是「打扰是稀缺资源」的执行体。想打断人，只能在报告里写"受阻 + 一个问题"，由主控决定是否转给人。
2. **QA 不能写**：只审不改，修复必须回原票 owner。运动员兼裁判是历史血案的根因。
3. **主控只能派这两种**：`allowedAgentPresets` 白名单卡死，避免模型临时发明角色。

## 安装与移除

源在仓库的 `bundles/fde-presets/`（两个文件：`package.json` + `cordis.patch.yml`），先同步到运行时，再从运行时安装：

```powershell
node scripts/sync-runtime.mjs          # bundles/ -> .dsh/bundles/
```

```text
plugin_manager action=install_bundle target=<仓库绝对路径>/.dsh/bundles/fde-presets
```

移除：

```text
plugin_manager action=remove_bundle target=@local/dsh-fde-presets
```

改完 patch 的流程是「改仓库 → sync-runtime → remove + install」。同一包名会报 `already-installed`，所以必须 remove 再 install（或升 `package.json` 的 version）。

## 验证

- `plugin_manager action=list_bundles` 里能看到 `@local/dsh-fde-presets`，`rows` 含 `preset-fde-lead` / `preset-fde-worker` / `preset-fde-qa`，`enabled: true`，无 `error`。
- 新建会话时，预设选择器里出现「FDE 主控 / FDE 逐单 / FDE 验收」。
- 真验证：选「FDE 主控」，让它派一张票给 Worker，看子会话是不是用了 `fde-worker` 的工具集（没有提问工具）。

## 与技能的关系

- 技能本身不依赖预设：`SKILL.md` 写了退回规则，预设没装也能同屏做完。
- 预设也不依赖技能：它们只是工具集 + persona，不加载 `all-in-fde`。
- 两者靠 `agent_preset` 名字对齐，改名字要同步改 `SKILL.md` 的派发表。

## 已知边界

- 子代理的模型路由由 `agent-default-model` 与子代理 tool 的 `agentOptions` 决定；这里没写死模型，用 profile 默认。
- 会话一旦开始就保留启动时的插件版本；改了预设要在新会话里验证。
- 预设激活失败会留在名单里带诊断信息，不会静默消失——这时先看 `list_bundles` 的 `error`，再决定修 patch 还是移除。
