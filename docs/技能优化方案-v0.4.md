# all-in-fde 技能优化方案（0.4.0）

> 输入：一次真实项目（一码通·产品溯源管理平台）的复盘 —— `docs/all-in-fde-使用反馈-一码通溯源.md`。
> 原则：只改「能被判据/脚本执行」的地方；写不成的，不进技能。
> 结论：反馈里的 5 条技能问题 + 7 条流程问题，全部落成规则或脚本；版本 0.3.3 → 0.4.0。

## 2. 新增/修改的脚本

| 脚本 | 状态 | 关键行为 |
| --- | --- | --- |
| `card-evidence.mjs` | 新增 | 解析卡片表格（3–5 项）；未点选退出 1；有问题写 FAIL；其余九项取自 `--from`；写 `signature` 与 `revision/supersedes` |
| `e7-fresh-copy.mjs` | 新增 | 复制项目（排除 `.git/node_modules/dist/data/.fde-tmp/.cache/*.db`）；`--run` 执行 install + check；输出可贴进 E7 的 JSON |
| `verify-evidence.mjs` | 改 | `--strict`；E6-9 PASS 必须 `by.kind=card/human` + `signature`；同 `gate+target+revision` 重复检测；按 `gate/target` 汇总 |
| `check-tickets.mjs` | 改 | 三阶段禁第三态；勾①必须有交付回执；挂 REQ >3 前缀告警；保留依赖环检测 |

## 4. 验收（本次改动的自检）

1. `node scripts/check-skills.mjs` 退出 0（版本一致、必需文件齐）。
2. 新脚本 `node --check` 语法通过。
3. 用真实项目做反向测试：
   - `card-evidence.mjs` 对未点选的卡片必须拒绝（退出 1）；
   - 对全部点选的卡片生成带 `signature` 的 E6 证据，且 `verify-evidence --strict` 通过；
   - `check-tickets.mjs` 对含 `◐` 或空回执的票报错；
   - `e7-fresh-copy.mjs` 复制后不含 `node_modules`/`data`/`.git`。
4. 未改变任何 v0.3.x 的既有约定（票号、门 ID、证据字段），只做增量。

## 5. 明确不做

- 不把「AI 自测通过」包装成 E6：验收必须有人。
- 不引入新的门 ID：31 条保持冻结，新约束挂在既有条目下。
- 不替项目决定业务：只统一「证据怎么算数」。
