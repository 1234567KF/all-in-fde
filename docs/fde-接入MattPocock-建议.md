## 一、提问纪律 → understand.md §阶段 A

**解决什么问题**：理解卡上那 3–7 条疑问现在想什么时候问就什么时候问，一条问题可能建立在另一条还没回答的问题之上，AI 只能靠猜；而且没有规定"哪些事该查、哪些事该问人"。

**借鉴来源**：Matt Pocock 的 `grilling` skill（他安装量最大的技能背后的机制）。

### 拟插入文字（放在「### 人回复」之前）

```markdown
### 提问排期纪律（阶段 A/B 通用）

疑问不是平铺的一张清单，是一棵树：有些疑问的答案决定另一些疑问能不能问。按层分批问：

1. **一轮问完当前能问的全部疑问**。依赖未回答疑问的后续问题留到下一轮，不许靠猜测答案提前问。
2. **每条疑问必须带推荐假设**——这条已有。措辞让人回答「是」即接受推荐，不同意才需要打字改。
3. **能自己查到的不许问人**。事实性问题（代码现状、环境、文档里写了的东西）派只读子代理去查；只有需要人拍板的决策才进疑问清单。查证中的问题属于下一轮，不阻塞本轮其余疑问。
4. **出口判据收敛于 S13**：疑问树问到「采集表 S13 没有待确认项」即可停，不追求穷尽整棵决策树。用户说「够了，直接出卡」视为强制收敛，剩余假设如实记入 S13。

常见错补充：
- **一次只问一个问题来回十几轮**：零散打断人，且每轮都在重付上下文成本。一轮一批。
- **问人自己能查的事**：把查证的活推给人，是 AI 失职，不是谨慎。
- **前置未决就把下游问题抛出去**：得到的回答建立在猜测之上，返工比多等一轮更贵。
```

## 二、宽重构例外 → slice.md §怎么做

**解决什么问题**：切片铁律要求"一票一条能演示的竖切路径"，但有一类活天生没法竖切——改一个列名、换一种共享类型，改动瞬间波及全库所有调用点，任何单票都保不住 `check` 绿。目前 fde 对这种活没有切法，只能塞进高难票硬扛。

**借鉴来源**：Matt Pocock 的 `to-tickets` skill 中的 expand–contract 规则。

### 拟插入文字（放在第 2 步「按模块+路径分组」之后、「定轨道」之前）

```markdown
2b. **宽重构例外（expand–contract）**：一次机械性改动（重命名列、替换共享类型、统一枚举值）爆炸半径覆盖全库、无法竖切成可演示路径时，不强套竖切，改按三段排票：

   - **expand**：新旧两种形态并存建票（加新列/新类型，旧的不删），单独一票；
   - **migrate**：按爆炸半径分批迁移调用点，一批一票，每票阻塞于 expand，旧形态仍在所以批批可保 `check` 绿；
   - **contract**：全部迁完后删旧形态一票，阻塞于所有 migrate 票。

   分批仍保不住绿的（如全局类型推断连锁失败）：各批共享一条集成分支，全部阻塞到最后一张「集成验证票」，绿只在验证票上承诺。此时「一票一演示路径」按 SKIP 记录在交付回执（理由：宽重构，验收谓词改为批次退出码 + 最终验证票），不算违规。

   宽重构票的授权范围要写明爆炸半径边界（哪些目录在本批、哪些在后续批），防止 Worker 顺手全量替换。
```

### 配套小改（同文件，票面字段说明处补一句）

```markdown
票面「Spec」与「交付回执」引用 spec 时，优先引章节锚点而非文件路径；spec 里的状态机、schema、类型定义这类决策性内容可以内联进票，实现细节和代码片段不要抄进票——会随实现过期。
```

## 三、交接文档模板 → SKILL.md 临时产物一节

**解决什么问题**：SKILL.md 已约定 `.fde/` 放 handoff，但没有任何地方定义 handoff 长什么样、什么时候写、下个会话怎么消费。跨会话续作目前全靠扫产物文件，接不回"这轮聊到哪了"的过程信息。

**借鉴来源**：Matt Pocock 的 `handoff` skill（三条核心规则，落点从 OS 临时目录改到 `.fde/handoff/`）。

### 拟插入文字（SKILL.md「四条硬规矩」表格之后）

```markdown
### 会话交接件（handoff）

`.fde/handoff/<日期>-<动作>.md`：会话中途要换人、换会话、或预计上下文将满时写一份，供新会话冷启动续作。「先读现场」扫到 handoff 时，以最新一份为准接动作，产物状态仍以文件扫描为准（handoff 说的是意图，产物说的是事实，冲突信事实）。

四节，从上到下：

1. **下个会话要做什么**：一句话目标 + 停在哪个动作（用「先读现场」的动作名）。
2. **本轮结论**：只写产物文件里没有的信息——人已拍板但还没回写规格的决定、被否决的方案与否决理由、踩过的坑。**已经写进 brief/采集表/PRD/spec/票的内容一律不复述，给路径指针。**
3. **待人事项**：未闭环的人审触点、HOLD/待确认项，逐条含具体可答的问题（不写「请补充信息」这种没法答的）。
4. **下一步加载**：写明下一个会话该读哪份 reference、该跑哪个脚本。

硬规矩：
- 敏感信息（密钥、内网地址、账号）不落 handoff，与交付前内网坐标扫描同一口径。
- handoff 是过程件不是证据：不进 `evidence/`，不参与门禁校验，E5/E6 的 evidence 字段不许指向它。
- 一次会话最多收尾写一份；重复写覆盖同名文件，不堆时间戳版本。
```
