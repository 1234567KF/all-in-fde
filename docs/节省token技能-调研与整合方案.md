# 节省 token 技能：调研、拆解与整合方案

- 对象：`1234567KF/ultra-cost-effective`、当前主流 token 节省方案、你现有的技能库
- 目标：博采众长，但不叠加成一堆互相打架的规则；每一层都能被 `dsh-cost` 验证是否真的省
- 结论基于两类数据：仓库源码/文档，以及你本机 30 个会话、2,489 次调用的真实账单

---

## 0. 五条结论

1. **值得借的不是“七层”，而是它的分层思维、预设、可逆压缩、冲突检测、子代理 brief 和 ROI 意识。**
2. **不能借的是 Claude Code 专属 hooks、自动管道注入、代码压缩、技能 stub，以及“60–90%”这类没有对照组的数字。**
3. **外部方案分五类干预点**：输入压缩、会话状态管理、输出塑形、编排（路由/调度/缓存）、技能封装。每类都有适用边界，不能全都开。
4. **你的账单决定了优先级**：高峰时段占 69.8%，仅调度就能省约 35%；输出占 40%，缓存命中输入占 35%，未命中占 25%。所以先做“时间 + 输出/effort + 上下文纪律”，压缩工具输出排后面，前缀/预热几乎可以不做。
5. **不混乱的唯一做法**：一个薄入口、三条命令、一张“什么能压/什么不能压”的矩阵、一条度量（每合格交付物成本）。先上 3 个低风险杠杆，8 对 A/B 过关再加。

## 1. `ultra-cost-effective` 拆解

仓库：<https://github.com/1234567KF/ultra-cost-effective>（个人项目，0 star，最后推送 2026-08-13，未见第三方复现）

### 1.1 它做对的六件事

| 做法 | 为什么值得借 |
| --- | --- |
| 分层：L0 监控、L1 输出/上下文压缩、L2 前缀、L3 预热、L4 技能加载、L6 A2A、L7 路由 | 把“省 token”拆成可分别验证的干预点，而不是一句口号 |
| 三档预设 quick/standard/extreme | 用户不需要理解每一层，按场景选档；但档位应是“开哪些杠杆”，不是“压得多狠” |
| 可逆：tokenforge `--store` + session-memory `retrieve` | 压缩必须能取回原文，否则错误无法恢复；这是安全底线 |
| 冲突检测：检测到第三方压缩器就跳过 | 双重压缩是最常见的“越省越贵”来源 |
| Agent Spawn 规则：给子代理传摘要，不传完整历史 | 直接命中多代理场景的最大浪费点 |
| 模型路由 + 成本保护 + 熔断 | 按任务复杂度选模型，比无脑压缩更有效；但规则要简单、可回退 |

另外，它的 `TOKEN-MONITOR-SPEC.md` 选择“只读会话 JSONL、零侵入”，方向是对的；这正是我们 `dsh-cost` 的做法。

### 1.2 三类硬伤

**（一）事实层：价格、缓存、TTL 都不对**

- 它用的 DeepSeek 价格是 2026-06 的旧价（Pro ¥3/15、Flash ¥1/5、缓存 ¥0.025/0.02）。当前官方 V4.1 Flash 是高峰 ¥2/8、低谷 ¥1/4；Pro 是高峰 ¥9/27、低谷 ¥4.5/13.5。缓存杠杆是 50 倍，不是 120 倍。
- “DeepSeek KV Cache TTL 5 分钟”没有官方依据；5 分钟是 Anthropic 的缓存 TTL，被误套到了 DeepSeek。基于这个假设做预热/调度会误判。
- 它的 L1 共享前缀示例自己算出来只有 **17%** 节省，但对外仍写“命中率 >90%、120x 杠杆”。400 token 的前缀放进 19 万 token 的上下文里，占比 0.2%，数学上不可能有大收益。

**（二）工程层：Claude Code 专属，且部分做法危险**

- `PreToolUse` hook 自动把命令改写成 `cmd | node tokenforge.cjs compress`：
  - 改变退出码语义（管道最后一段的退出码）；
  - 破坏需要 TTY 的命令（`git push`、`npm install`、交互式 CLI）；
  - PowerShell 与 bash 的引号/编码/重定向规则不同，容易把命令改坏；
  - DSH 没有这套 hook，直接搬不过来。
- `compressCode` 会把函数体折叠成一行、删注释、按行数截断。对“读代码”也许能看，对“改代码”是灾难：模型看到的是残缺语法，容易改错。**代码只能换读取模式（签名/地图/行区间），不能做有损压缩。**
- `compressJson` 对数组采样、字符串截断。用于日志可以，用于接口数据/配置/业务 JSON 会丢字段，后续代码可能直接跑错。
- “非活跃技能压成 25 token stub”：DSH 本来就是“元数据常驻、SKILL.md 按需加载”，再压 stub 会让技能无法被发现，收益也远小于风险。

**（三）度量层：把“压缩率”当成了“节省率”**

- `bench-results.json` 测的是**单段文本的字符/估算 token 压缩比**，不是端到端账单。`totalPct 68.7%` 是 10 个样本的加权压缩率，不是会话成本下降。
- “187 项测试”测的是脚本行为（去重、折叠、JSON 合法性），没有对照组、没有质量评估、没有返工统计。
- 它的 token monitor 公式 `cacheMiss = input_tokens - cache_read_input_tokens` 与 Anthropic 语义冲突：Anthropic 的 `input_tokens` 本身就不含缓存读取，这样会少算未命中，极端情况为负。DeepSeek 的 Anthropic 兼容层是否同义要按 provider 校验；我们 `dsh-cost` 直接读四个桶相加，不做减法。
- 结论：**它的数字不能作为“已经省了 60–90%”的证据，只能作为“这些手段在局部能把文本压小”的参考。**

### 1.3 借鉴清单

| 模块 | 判断 | 怎么用 |
| --- | --- | --- |
| 七层架构 | 借壳，不借层数 | 简化成 3 层：任务前、执行中、交付前；每层只放 1–2 个动作 |
| quick/standard/extreme 预设 | 借 | 改成“观察 / 标准 / 激进”三档，默认标准=少做事 |
| tokenforge 输出压缩 | 借思路，重写 | 只允许日志/JSON；必须可逆；不碰代码/文档 |
| 代码压缩 | 弃 | 用 read 的 signatures/map/lines 模式替代 |
| 共享前缀模板 | 弃 | DSH 的 system prompt/tools 已固定；不要为了 400 token 改前缀，反而可能破坏缓存 |
| 长上下文预热 | 谨慎/弃 | 预热本身是全价调用，是否命中不确定；除非 A/B 证明，否则不做 |
| 技能 stub | 弃 | DSH 已按需加载；保持元数据完整 |
| 模型路由 | 借，简化 | 只做“任务类型 → 模型/effort”三档，不做关键词魔法 |
| 上下文三色灯 | 借阈值 | 60% 提醒、80% 强制收口；但优先用 DSH 原生 compaction |
| Agent Spawn 摘要 | 强借 | 子代理只给目标、输入、约束、输出格式；不回传完整历史 |
| 冲突检测 | 强借 | 同一段内容只允许一个压缩器；检测到已压缩就跳过 |
| session-memory/retrieve | 强借 | 压缩必须带原文索引，模型可随时取回 |
| token monitor | 弃 | 用 `dsh-cost`，口径已验证 |
| 工作流预设（研究/审计/迁移/重构） | 借 | 变成任务类型 playbook，而不是压缩级别 |
| ROI 追踪 | 借 | 直接用 `dsh-cost compare` |

## 2. 外部方案调研：五类干预点

| 干预点 | 代表方案 | 真实收益 | 主要风险 | 对你有用吗 |
| --- | --- | --- | --- | --- |
| 输入压缩（工具输出/JSON/日志） | Headroom、RTK、lean-ctx、tokenforge | Headroom 实测 21–57%；RTK 单命令 60–90%；lean-ctx 单命令 60–99% | 丢错误信息、双重压缩、破坏退出码 | 中：代码/运维任务有用，长文办公用处小 |
| 读取路由（签名/地图/行区间/缓存） | lean-ctx 的 10 种 read mode | 重复读 ~13 token；map/signatures 省 70–95% | 看不到关键实现细节 | 高：IT/游戏开发首选 |
| 会话状态（压缩/笔记/子代理） | Anthropic compaction、note-taking、subagents | 长任务可继续；子代理只回 1–2k token | 压缩丢细节、压缩后 cache miss | 高：你的长文任务和多代理都在用 |
| 输出塑形（简洁/不重述/只给 diff） | Caveman、Headroom output shaper | 视任务而定；Caveman 有“有时更贵”的公开讨论 | 话太少导致多轮追问，反而更贵 | 中：聊天/状态汇报有用，交付物不能压 |
| 编排（模型/effort/时段/缓存） | 各家 router、DeepSeek 峰谷价 | 峰谷 2 倍；effort 高低差数倍 | 质量漂移、缓存失效 | 最高：你的账单 69.8% 在高峰 |
| 技能封装（渐进披露） | Anthropic Skills、ADR-0009 | SKILL.md 从 1500 行降到 400 行，官方称 40–60% 效率提升 | 拆得太碎导致发现困难 | 高：你的 all-in-md 有 466 行/36KB |

### 2.1 Headroom：目前证据最扎实的“输入压缩层”

<https://github.com/headroomlabs-ai/headroom>

值得学的不是它的代理，而是四条设计：

1. **Live-zone only**：只压新增的工具输出/最新一轮，冻结前缀保持逐字一致，缓存不被打穿。
2. **可逆 CCR**：原文落本地，模型可 `retrieve`。
3. **CacheAligner**：识别会打穿 KV 缓存的高变动内容，但它不改写 prompt，只提示。
4. **输出侧留 10% 对照组**：输出节省是反事实，必须用 holdout 才敢标“measured”。

它自己给的实测是 21–57%（重复 JSON/日志更高，散文很低），并明确说“如果 provider 原生压缩已经覆盖你的流量，你可能不需要它”。这个诚实度值得学。

### 2.2 lean-ctx：读取路由 + 缓存，思路最适合 IT/游戏

<https://github.com/mvanhorn/lean-ctx>

- 10 种读取模式：`full` / `map` / `signatures` / `diff` / `lines:N-M` / `aggressive`。
- 重复读同一文件 ~13 token（缓存命中）。
- 56 个 shell 输出模式（git/npm/cargo/docker/kubectl）。
- 68 个 MCP 工具、会话记忆、上下文预算。

借：**先 map/signatures，再按行读，重复读走缓存**。这是“减少上下文”的正道，比压缩代码安全。
不借：68 个工具的复杂度、全局 shell hook。

### 2.3 RTK：命令感知的 shell 输出压缩

<https://github.com/rtk-ai/rtk>

- 单 Rust 二进制，`rtk git status` / `rtk cargo test` 等 30+ 命令，按命令定制过滤。
- 实测单命令 60–99%，但这是**命令输出**的压缩率，不是会话成本。
- 通过 Claude Code PreToolUse hook 全局改写命令。

借：**按命令类型做过滤器**（测试只留失败用例、git 只留摘要、构建只留错误），而不是通用文本截断。
不借：全局前缀 `rtk`、hook 改写；DSH 里应由技能在需要时显式调用。

### 2.4 LLMLingua：模型级 prompt 压缩，适合“长散文”，不适合代码/合同

<https://github.com/microsoft/LLMLingua>

- 论文声称最高 20x 压缩、性能损失很小；实际需要小模型做 token 分类，有延迟和部署成本。
- 对重复度高、信息密度低的文本有效；对代码、表格、法律条款这类“删一个词就变意思”的文本风险高。

借：**只对“可丢词”的长 prose 做试验**，且必须用你的任务做质量评估。
不借：默认开启、对代码/标书正文使用。

### 2.5 Caveman：输出端的“极简话术”，有时反而更贵

<https://www.getcaveman.dev/news/does-the-caveman-skill-save-money>

- 让模型像原始人一样说话，减少客套、冠词、解释。
- 公开讨论的结论是“有时省，有时更贵”：话太少导致用户追问、模型猜错、返工增加。

借：**去掉“好的，我来…”这类前言、不重述输入、只给结论和 diff**。
不借：把交付物本身写短；长文/标书/PPT 的内容长度是产品，不是浪费。

### 2.6 Anthropic 的官方口径：上下文工程，不是“压缩工程”

<https://www.anthropic.com/research/effective-context-engineering-for-ai-agents>

四个可直接落地的结论：

1. **Context rot**：上下文越长，召回越差；目标不是“塞满”，是“最小高信号集合”。
2. **Just-in-time**：保留文件路径/查询/链接，用工具按需取，而不是预加载全部。
3. **Compaction**：接近上限时摘要重启；优先清工具结果，这是最轻的压缩。
4. **Sub-agents**：子代理深入探索，只回 1–2k token 摘要。

配套的技能规范（<https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices>）明确：启动时只预加载技能元数据，`SKILL.md` 按需读，其他文件再按需读。**“技能本身要薄”是官方建议，不是社区偏方。**

### 2.7 证据强度分级

| 等级 | 含义 | 代表 |
| --- | --- | --- |
| A | 有对照组/质量评估/可复现 | Headroom 的 4 场景 + 10% holdout；Anthropic 的 compaction 实践 |
| B | 有单点测量，但没有端到端成本/质量 | RTK、lean-ctx、tokenforge 的压缩率 |
| C | 只有算术或个案 | “60–90% 综合节省”、Caveman 的省钱说法 |

**只把 A/B 级手段放进默认策略；C 级一律先做小实验。**

## 3. 先算账：你的钱花在哪，杠杆上限是多少

### 3.1 账单结构（2026-11-18 快照）

- 30 个会话、2,489 次调用、87 轮，总花费 **¥46.118**
- 高峰时段 **69.8%**；全部放低谷约 ¥30.03，理论省 **34.9%**
- 成本构成：输出 **40%**、缓存命中输入 **35%**、未命中输入 **25%**
- 缓存命中率 98.9%，但命中量是未命中的 87 倍；缓存省下 ¥777 是反事实，不是现金
- 子代理约 **19%**
- 单轮最贵：四个 PPT 技能并行 ¥5.30；长文改写 ¥4.00；压缩后全量 miss ¥2.89（命中率 0.9%）
- `all-in-md` 生效期间占 55.3%；它的 SKILL.md 36KB/466 行，reference.md 35.6KB

### 3.2 杠杆上限（理论上限，不是承诺）

| 杠杆 | 影响的成本项 | 算法 | 你的上限 |
| --- | --- | --- | ---: |
| 低谷调度 | 全部 | 50% × 69.8% | **34.9%** |
| 输出/effort 降档 | 输出 40% | 机械任务 output -30% × 60% 任务占比 | **7–12%** |
| 上下文减 30% | 命中+未命中 60% | 60% × 30% | **18%** |
| 步数减 20% | 输入 60% | 60% × 20% | **12%** |
| 子代理 brief 减 30% | 子代理 19% | 19% × 30% | **5.7%** |
| 工具输出压缩 50% | 若工具占上下文 20% | 60% × 10% | **6%** |
| 技能瘦身 10k→3k | 19 万上下文 | 60% × 3.7% | **2.2%** |
| 模型路由 pro→flash | Pro 占 12% | 12% × 50% | **6%** |
| 避免一次压缩 miss | 单次 ¥2.9 | 2.9 / 46.1 | **6.3%/次** |
| 共享前缀 +400 token | 19 万上下文 | 60% × 0.2% | **0.1%** |
| 缓存预热 | 不确定 | 预热本身全价，可能负收益 | **≈0 或负** |

这张表说明三件事：

1. **前缀/预热/技能 stub 在你的账单里是噪声**，不值得为它们增加复杂度。
2. **时间调度是唯一“零质量风险、30% 量级”的杠杆**，应该第一优先。
3. **压缩工具输出不是万能药**：工具输出只占上下文一部分，压到极限也就 6% 量级；而且有质量风险。

### 3.3 排序结论

```
第一优先：低谷调度（0 风险，~35%）
第二优先：输出/effort 纪律（低风险，~8–15%）
第三优先：上下文纪律（低风险，~10–18%）
第四优先：子代理 brief（低风险，~5%）
第五优先：工具输出压缩（中风险，~0–6%）
第六优先：模型路由（中风险，~0–6%）
不做：共享前缀、缓存预热、技能 stub、代码压缩
```

## 4. 整合方案：一个策略、三层、五个杠杆、一个度量

### 4.1 一个入口：`token-budget` 薄技能

> 已落地为 `skills/token-budget/`（技能名 `token-budget`）：`plan` / `brief` / `squeeze` / `verify` 四个动作，`scripts/` 下为无依赖 Node 实现，`references/` 为按需加载的策略与 playbook。`all-in-fde` 入口以后存在时，在它第一步加载本技能即可。

不要做“七个 always-on 规则文件”。做一个薄入口，只负责三件事：**判断、分发、验收**。

```
skills/token-budget/
  SKILL.md                 # ≤120 行 / ≤2KB，只写触发条件、命令、红线
  references/
    policy.md              # 决策表 + 压缩矩阵
    playbook-code.md       # IT/游戏
    playbook-doc.md        # 长文/PPT
  scripts/
    budget.mjs             # 读 dsh-cost + 上下文压力，输出“这次该怎么跑”
    brief.mjs              # 生成子代理 brief
    squeeze.mjs            # 只压日志/JSON，可逆
```

三条命令，不再增加：

| 命令 | 做什么 | 何时用 |
| --- | --- | --- |
| `plan` | 判断任务类型、当前峰谷、上下文压力，给出本次 playbook 和预算 | 任务开始时 |
| `brief` | 把“目标/输入/约束/输出格式/返回上限”写成子代理 brief | spawn 子代理前 |
| `squeeze` | 压缩日志/JSON，原文落盘，返回 `id` 可 retrieve | 工具输出很长时 |
| `verify` | 调 `dsh-cost compare`，出 A/B 结论 | 每轮实验后 |

（`verify` 是第四条，但它是复用现有 CLI，不算新机制。）

### 4.2 三层：任务前、执行中、交付前

| 阶段 | 动作 | 省的是哪一项 | 风险 |
| --- | --- | --- | --- |
| 任务前 | 判类型、选 playbook、看峰谷、设预算、决定是否拆子代理 | 避免一开始就选错模型/塞满上下文 | 低 |
| 执行中 | 按需读（map/signatures/lines）、artifact-first、日志压缩、子代理 brief、60% 提醒 | 命中+未命中输入、步数 | 低–中 |
| 交付前 | 只回 diff/摘要/路径，不重述全文；记录质量判定 | 输出 | 低（但交付物不能压） |

### 4.3 五个杠杆

1. **Schedule**：长任务尽量安排在低谷（晚 18:00 后、周末、节假日）；高峰时段先做短任务/审阅，把长生成留到低谷。`plan` 直接提示“现在高峰，预计 2 倍价”。
2. **Output/effort**：机械任务（抽取、格式转换、表格填充、文件改名）用低 effort；架构/歧义/评审用高 effort。输出只给结论、diff、路径，不重述输入。
3. **Context**：先大纲/索引，再按节读；不把整篇文档贴进对话；工具结果落文件，对话只留路径和摘要；同一文件不重复整读。
4. **Isolation**：探索、审阅、并行生成走子代理；brief 只给必要信息；子代理返回 ≤1.5k token，详细内容写文件。
5. **Routing**：默认 flash；只有“架构/方案/高风险评审”才升 pro；不在会话中途频繁换模型（会破坏缓存）。

### 4.4 一张压缩矩阵（红线）

| 内容类型 | 允许压缩 | 手段 | 可逆 | 上限 |
| --- | --- | --- | --- | --- |
| 测试/构建日志 | ✅ | 只留失败用例、错误行、栈顶/栈底 | 必须 | 80% |
| JSON/API 响应 | ✅ | 结构摘要、数组采样、字段裁剪 | 必须 | 70% |
| git/docker/kubectl 输出 | ✅ | 按命令模板过滤 | 必须 | 80% |
| 源代码 | ❌ | 只能换读取模式（map/signatures/lines） | — | — |
| 文档正文/合同/标书 | ❌ | 只能分段读、diff 改 | — | — |
| 对话历史 | ⚠️ | 只用 DSH 原生 compaction；优先清工具结果 | 由 harness 保证 | — |
| 技能说明 | ⚠️ | 只做渐进披露，不做运行时有损压缩 | — | — |
| 交付物（docx/pptx/pdf） | ❌ | 不压；长度是产品 | — | — |

**判定规则：删掉一个词会不会改变事实/法律/代码语义？会，就不许压。**

### 4.5 冲突与优先级

```
正确性 > 省 token
DSH 原生 compaction/spill > 自定义压缩
一个内容只允许一个压缩器（检测到已压缩就跳过）
能换读取模式就不做文本压缩
能落文件就不塞对话
能拆子代理就不主线程硬扛
缓存命中率下降 > 5 个百分点 → 回滚
```

### 4.6 关闭开关

- 提示词里写 `#cost-off`：本任务不启用任何压缩/裁剪。
- 环境变量 `TOKEN_BUDGET=off`：全局关闭。
- 单一杠杆可单独关：`#no-squeeze`、`#no-brief`。
- 任何一次 A/B 没有通过质量门，默认关掉该杠杆，而不是“再观察观察”。

## 5. 技能结构：怎么做到“薄而不乱”

### 5.1 SKILL.md 草案（≤120 行）

```markdown
---
name: token-budget
description: 在不降低交付质量的前提下，按任务类型选择 token 预算策略；提供 plan/brief/squeeze/verify 四个动作。
triggers: 省token, 预算, token budget, 成本, 节省, 贵
---

# token-budget

## 何时用
- 任务预计超过 10 轮，或上下文 > 60%
- 要 spawn 子代理
- 工具输出 > 2k token
- 当前处于高峰时段且任务较长

## 四个动作
1. plan：判断类型（code/doc/ppt/research），输出本次策略和预算
2. brief：生成子代理 brief（目标/输入/约束/输出格式/返回上限）
3. squeeze：仅日志/JSON，原文落盘，返回 id
4. verify：调用 dsh-cost compare

## 红线
- 不压代码、文档正文、合同、交付物
- 不叠加压缩器
- 不改 system prompt/tools 前缀
- 交付质量优先；省 token 不是目标

## 预算
- 子代理返回 ≤ 1.5k token
- 技能自身加载 ≤ 2k token
- 单次 squeeze 只处理当前工具输出，不重写历史
```

### 5.2 渐进披露

- `SKILL.md` 只放“何时用/四个动作/红线/预算”。
- 详细决策表放 `references/policy.md`（≤8KB），只在 `plan` 时读。
- 两类 playbook 分开，互不污染。
- 不要把 36KB 的规则塞进入口；`all-in-md` 的教训就在眼前（466 行/36KB）。

### 5.3 与现有技能的关系：包装，不替代

| 现有技能 | token-budget 做什么 | 不做什么 |
| --- | --- | --- |
| `all-in-md` | 在它前面加“大纲→分节读→diff 输出”；在它后面加 verify | 不改它的审阅标准、文风规则 |
| `ppt-master`/`dashi-ppt` 等 | 强制 artifact-first：脚本生成、只回路径和摘要 | 不改模板、不压交付物 |
| 编码/设计类 | 提供 map/signatures/lines 读取顺序、日志压缩、子代理 brief | 不替代规划、不压源码 |
| `kf-kb-envoy` | 子代理 brief + 返回上限 | 不改知识库规则 |

**原则：token-budget 是“流程层”，领域技能是“内容层”。流程层不得覆盖内容层的判断。**

## 6. 两类工作的 playbook

### 6.1 IT / 游戏设计

| 阶段 | 动作 | 省哪项 | 风险 |
| --- | --- | --- | --- |
| 进入仓库 | `glob` 结构 → `grep` 定位 → `read` 只读目标文件的行区间 | 输入 | 低 |
| 理解代码 | 先 signatures/map，再按需 full；同一文件不重复整读 | 输入/步数 | 中（可能漏细节） |
| 跑测试 | 只保留失败用例和错误行；通过的用例折叠 | 输入 | 低 |
| 改代码 | 只输出 diff；不重贴整个文件 | 输出 | 低 |
| 探索 | 子代理带 brief 去搜，回 1–2k 摘要 | 输入/步数 | 低 |
| 模型 | 默认 flash；架构/疑难才 pro；机械任务低 effort | 输出 | 中 |

### 6.2 长文办公 / PPT

| 阶段 | 动作 | 省哪项 | 风险 |
| --- | --- | --- | --- |
| 读文档 | 先生成大纲/章节索引（标题+行号+摘要），再按节读 | 输入 | 低 |
| 审阅 | 一次只读相关章节；引用“文件+行号”，不贴全文 | 输入 | 低 |
| 改写 | 输出 diff/替换块；原文件落盘；不重述全文 | 输出 | 低 |
| 扩写 | 先给结构/要点，确认后再展开；避免整篇重写 | 输出/步数 | 低 |
| PPT | 用模板/脚本生成；对话只回文件路径、页数、摘要 | 输出 | 低 |
| 压缩 | 只在章节边界做；保留“决策/术语/未决问题”清单 | 压缩后 miss | 中 |

**长文任务的第一原则：文档在磁盘上，不在对话里。** 对话里只放“索引 + 结论 + diff”。

## 7. 实施路线（四周）

### 第 0 周：基线（已完成大半）

- `dsh-cost` 已能出账单；给任务打 `#task=...`，先积累 2 周基线。
- 不改任何技能，避免“边改边测”。

### 第 1 周：薄技能 + 两个安全脚本

- 写 `token-budget` 的 SKILL.md + policy.md。
- `brief.mjs`：输入任务/文件/约束，输出子代理 brief。
- `squeeze.mjs`：只处理日志/JSON，原文落 `data/squeeze/<id>`，返回 `id`。
- 不做自动 hook，不做代码压缩。

### 第 2 周：接入两个 playbook

- 长文：给 `all-in-md` 加“大纲→分节→diff”流程（只改调用方式，不改规则）。
- PPT：四个 PPT 技能统一“artifact-first”，只回路径和摘要。
- 编码：在提示里固定“先 map/signatures，再 lines”。

### 第 3 周：A/B

- 每个任务类型 8 对，ABBA 顺序，同一时段。
- 主指标：每合格交付物成本；辅指标：命中率、输出、步数、返工。
- 质量门：合格率不低于基线。

### 第 4 周：固化/砍掉

- 只保留通过质量门且净节省 ≥15% 的杠杆。
- 其余写进“暂不启用”，而不是继续堆规则。
- 更新技能 README，记录模型、价格版本、样本量、夹具哈希。

### 验收标准

| 条件 | 门槛 |
| --- | --- |
| 净成本下降 | ≥15%（至少一个任务类型） |
| 质量 | 合格率不低于基线；无新增 P0 错误 |
| 返工 | 轮次/追问不增加 |
| 缓存 | 命中率不下降超过 5 个百分点 |
| 可复现 | 同夹具、同模型、同时段，8 对以上 |

达不到就**不上线**；不要用“反事实缓存节省 ¥777”来凑数。

## 8. 验证：怎么证明不是自嗨

### 8.1 指标

- 主指标：`(模型成本 + 返工成本 + 技能开销) / 合格交付数`
- 辅指标：每轮成本、每次请求平均上下文、输出 token、步数、重试、子代理成本
- 诊断指标：压缩后是否出现重复读取、是否出现“找不到原文”、是否 cache miss 激增

### 8.2 必须控制的混杂

| 混杂 | 控制 |
| --- | --- |
| 缓存冷热 | 首行唯一 `#run`；ABBA 交替；不“先跑完 A 再跑 B” |
| 峰谷 | 同一对同一小时；跨天按峰谷拆开 |
| 模型/effort | 固定 provider/model/effort，写进运行记录 |
| 输入漂移 | 夹具哈希；同一文件版本 |
| 返工 | 以“合格交付”为单位，返工算进成本 |
| 工具差异 | 记录搜索/重试/子代理数量；异常 run 剔除并说明 |

### 8.3 最小实验矩阵

| 任务类型 | 夹具数 | 对数 | 主要验证的杠杆 |
| --- | ---: | ---: | --- |
| 长文审阅 | 4 | 8 | 大纲+分节读、diff 输出 |
| 长文扩写 | 2 | 8 | 结构先行、分段展开 |
| PPT 生成 | 2 | 8 | artifact-first、脚本生成 |
| 编码/设计 | 2 | 8 | map/signatures、日志压缩、brief |

一个杠杆一次实验；不要“七层全开”再去归因。

## 9. 风险与反模式

| 反模式 | 后果 | 替代 |
| --- | --- | --- |
| 自动管道注入 | 改坏命令、丢退出码、TTY 失败 | 显式 `squeeze`，只处理允许的内容 |
| 压缩源代码 | 语法残缺、改错 | map/signatures/lines |
| 压缩文档正文/合同 | 事实/法律风险 | 分节读、diff 改 |
| 双重压缩 | 越压越贵、信息不可逆 | 冲突检测，一段只压一次 |
| 为了省 token 把输出写短 | 质量下降、返工 | 只删前言/重述，不删交付内容 |
| 频繁换模型/改前缀 | 缓存失效，账单反升 | 会话内固定；换模型另起会话 |
| 用压缩率当节省率 | 自嗨 | 端到端 A/B + 质量门 |
| 七层全开 | 无法归因、维护爆炸 | 一次只上一个杠杆 |
| 预热缓存 | 全价调用，可能不命中 | 不做，除非 A/B 证明 |
